# 중고 시세 조회

제품명을 입력하면 최근 30일 평균 거래 가격(번개장터 거래완료 기준), 지금 판매 중인 매물 가격(번개장터·당근마켓·중고나라), 다나와 새 제품 최저가를 함께 보여 주는 사이트입니다.

- 화면: GitHub Pages (`index.html`)
- 자료 조회: Supabase Edge Function `price` (`supabase/functions/price/index.ts`)
- 저장소 예시: `mykim-app/junggo` → 게시 주소 `https://mykim-app.github.io/junggo/`
- **발급받을 인증키 없음** (네이버 쇼핑 검색 API는 2026-07-31 종료되어 다나와로 대체)

## 1. 기존 Supabase 프로젝트 사용 가능 여부

MBTI·통관 조회(unipass)에 쓰는 프로젝트를 그대로 쓰면 됩니다. 새 프로젝트를 만들 필요가 없습니다.

| 확인 항목 | 기준 (무료 요금제) | 이번 사이트 추가 후 |
|---|---|---|
| 프로젝트당 함수 개수 | 최대 100개 | unipass + price = 2개 |
| 함수 호출 횟수 | 조직 전체 월 50만 회 | 조회 1번 = 1회 |
| Secrets(비밀값) | 프로젝트 공통 | 기존 `ALLOWED_ORIGIN`을 그대로 같이 씀 |

- `ALLOWED_ORIGIN`은 프로젝트 전체 함수가 같이 쓰는 값이라, unipass 때 `https://mykim-app.github.io`로 넣어 두었다면 추가 작업이 없습니다. 넣지 않았어도 코드 기본값이 같은 주소입니다.
- 무료 프로젝트는 오랫동안 사용이 없으면 일시 중지될 수 있습니다. 대시보드 첫 화면에 "Paused" 표시가 있으면 Restore를 누르면 됩니다.

## 2. Supabase 함수 만들기 (대시보드 방식)

1. supabase.com → 로그인 → 기존 프로젝트 선택
2. 왼쪽 메뉴 **Edge Functions** → **Deploy a new function** → **Via Editor**
3. 함수 이름을 `price`로 입력 (화면 주소와 맞춰야 하므로 정확히 `price`)
4. 편집기 내용을 모두 지우고 `supabase/functions/price/index.ts` 내용을 전부 붙여 넣기 → **Deploy function**
5. 배포 후 함수 목록에서 `price` → **Details**(또는 Settings) → JWT 검증 항목(화면에 따라 "Verify JWT" 또는 "Enforce JWT verification") **끄기** → 저장
   - 켜 두면 웹페이지에서 부를 때 401 오류가 납니다.
6. (선택) 당근 기준 동네를 송도동이 아닌 곳으로 바꾸려면 **Edge Functions → Secrets**에서 `DAANGN_REGION` 추가 (아래 4번 참고)

명령창 방식을 쓰려면 아래와 같습니다.

```bash
npx supabase login
npx supabase link --project-ref vewmmndhipvazzmttzzr
npx supabase functions deploy price --no-verify-jwt
```

## 3. 함수 점검

브라우저 주소창에 아래 주소를 넣습니다. (이 프로젝트 주소가 미리 들어 있습니다.)

```
https://vewmmndhipvazzmttzzr.supabase.co/functions/v1/price?q=닌텐도 스위치 OLED&forceFunctionRegion=ap-northeast-2
```

JSON 글자가 나오면 정상입니다. 확인할 곳은 다음과 같습니다.

- `"sold"` 안의 `"mean"`, `"median"`, `"count"`: 최근 30일 평균·중간 거래 가격과 거래 건수
- `"combined"` 안의 `"median"`: 지금 판매 중인 매물의 통합 중간값
- `"bunjang"`, `"daangn"`, `"joongna"`: 출처별 판매 중 매물 결과
- `"bunjang"`, `"daangn"`: 출처별 결과. 조회가 막히면 `"error"` 문구가 나옴
- `"new"` 안의 `"rep"`: 다나와 대표 제품과 최저가

오류별 조치:

- **401 오류:** JWT 검증이 켜져 있음 → 2-5 단계 확인
- **404 오류:** 함수 이름이 `price`가 아님
- **daangn의 `searched`가 0:** 당근이 빈 결과를 준 경우. 잠시 뒤 다시 조회. 계속 0이면 알려 주세요.

## 4. 당근 동네 바꾸기

화면의 검색창 아래 **당근 동네 → 바꾸기**에서 시도 → 시군구 → 동을 고르고 **적용**을 누르면 됩니다.

- **반경**(3·5·10·20·50km, 기본 10km): 당근은 동네 주변 매물이 적으면 전국 매물까지 섞어 보여 주므로, 고른 동네 중심에서 반경 안의 매물만 시세에 넣습니다. 매물마다 거래 희망 장소 좌표로 거리를 계산하며, 좌표가 없는 글(당근 글의 상당수)은 동 이름으로 추정합니다: 고른 동네와 같은 구의 동이면 반경 안("같은 구"), 같은 동의 다른 글에 좌표가 있으면 그 거리("약 6km"), 둘 다 아니면 위치 확인이 안 돼 제외합니다. 동별 거리는 조회할수록 쌓여 추정 범위가 넓어집니다. 목록에 "송도1동 · 2km"처럼 거리가 표시되고 제목 옆에 멀리 있어 뺀 건수가 나옵니다.
- **바로구매 포함**(기본 켜짐): 당근의 "바로구매" 매물은 택배로 바로 살 수 있으므로 반경·위치와 관계없이 포함합니다. 목록에 "· 바로구매"로 표시되고 제목 옆에 "먼 곳이지만 바로구매 N건 포함"이 나옵니다. 끄면 반경 안의 직거래 매물만 봅니다. (참고: 당근이 섞어 보여 주던 먼 지역 매물은 대부분 바로구매 매물이라, 켜 두면 사실상 전국 시세에 가까워집니다.)
- 고른 동네는 이 브라우저에 저장되어 다음 조회에도 그대로 쓰입니다. **기본(송도동)**을 누르면 처음 값으로 돌아갑니다.
- 결과가 화면에 있는 상태에서 동네를 바꾸면 당근만 새 동네로 바로 다시 조회합니다(번개장터·중고나라·다나와는 전국 기준이라 그대로).
- 시도·시군구 목록은 당근 지역 목록 화면에서, 동 목록은 그 시군구로 조회했을 때 함께 오는 주변 동네 목록에서 가져옵니다. 한 번 불러온 목록은 이 브라우저에 7일, 함수에 하루 동안 저장합니다.
- 동 목록을 처음 불러올 때 당근 요청 1회를 쓰므로, 바로 뒤의 당근 조회는 잠시 기다릴 수 있습니다.
- 동네를 고르지 않았을 때의 기본값은 Secrets의 `DAANGN_REGION`(없으면 `송도동-6543`)입니다.

## 5. GitHub Pages 게시

1. `index.html`의 `FUNCTION_URL`은 이미 `https://vewmmndhipvazzmttzzr.supabase.co/functions/v1/price`로 들어 있음 (수정 불필요)
2. GitHub에서 `mykim-app/junggo` 저장소를 Public으로 만들고 `index.html` 업로드 (다른 파일은 선택, 인증키는 어디에도 없음)
3. 저장소 **Settings → Pages → Deploy from a branch → main / (root) → Save**
4. 1~2분 뒤 `https://mykim-app.github.io/junggo/` 접속
5. `https://mykim-app.github.io/junggo/?q=제품명` 형태로 바로 조회 링크도 쓸 수 있음

## 계산 방식

**평균 거래 가격 (대표 값)**

- 번개장터에서 판매완료 처리된 글을 최신순으로 최대 400건 받아, 조회일 기준 최근 30일 안에 판매완료된 글만 사용
- 거래일은 글의 마지막 변경 시각(판매완료 처리 시점)으로 봄. 판매완료 표시 후 가격을 고친 경우 등은 구분할 수 없음
- 아래 판매 중 매물과 같은 기준으로 구매 글·부품용·액세서리·극단값을 제외한 뒤 평균·중간값·가운데 50% 구간 계산
- 기간은 주소에 `&days=60`처럼 넣으면 7~90일 사이로 바꿀 수 있음
- 당근마켓·중고나라는 웹 검색에서 거래완료 글을 보여 주지 않아 실거래 계산에는 들어가지 않음

**삼성 공식 보상판매 (갤럭시 검색 시)**

- 검색어에 "갤럭시"·"Galaxy"·"삼성"이 있으면 삼성 공식 보상판매 사이트(kr-samsung-tradein.likewize.com)에서 같은 모델을 찾아 용량별 보상가를 함께 표시
- 사이트와 같은 방식(공개키 교환 → 손님 로그인 → 암호화 요청)으로 기기 검색과 용량별 가격을 받음. 인증키 설정 불필요
- 용량별 등급 가격 중 가장 높은 가격이 사이트에서 "Excellent"로 표시되는 등급이며, 이 값을 표시
- 검색어와 모델명이 맞고 검색어에 없는 파생 모델(울트라·FE 등)이 아닌 기기만 표시(태블릿 Wi-Fi/5G처럼 둘 이상이면 최대 2개)
- 보상판매 대상이 아닌 모델(예: 아직 목록에 없는 신모델, 워치·버즈)은 "대상 목록에 없음"으로 안내
- 같은 검색어는 6시간 동안 저장해 두었다가 다시 씀

**검색어 다듬기**

- 흔한 오타는 고쳐서 검색: 에어콘 → 에어컨, 악세사리·엑세서리 → 액세서리
- 붙여 쓴 검색어의 앞 제조사 이름은 떼어 냄: "삼성창문형에어컨" → "삼성 창문형에어컨"
- 바꿔서 검색한 경우 화면 위에 안내 문구 표시

**판매 중 매물**

- 번개장터(관련도순 100건)·당근마켓(동네 주변 검색 결과)·중고나라(추천순 100건) 매물 중 광고, 판매완료, 구매 희망·매입·부품·고장 글, 검색어가 제목에 모두 들어 있지 않은 글(숫자는 앞뒤 숫자까지 구분), 형식적인 가격(1,111,111원 등)을 제외
- 숫자만 따로 쓴 검색어는 앞 단어와 묶어 모델명으로 봄: "아이폰 16" → "아이폰16"/"아이폰 16"만 일치. "16GB"·"아이폰6 16g"·"iPhone 5c 16GB"는 제외
- 모델 번호 뒤에 영문 한 글자가 붙은 다른 모델은 제외(6s·5c·16e 등, 용량 표기 16g·1t는 허용). 16e 시세는 "아이폰 16e"로 검색
- 검색어에 없는 파생 모델 글은 제외: 울트라·플러스(모델명 뒤 `+` 포함)·프로·맥스·미니·클래식·라이트·FE·엣지. 예: "갤럭시 S26"에는 S26+·S26 울트라가 섞이지 않음. 파생 모델 시세는 "갤럭시 S26 울트라"처럼 검색
- 케이스·필름·키보드 등 액세서리 단어가 있는 글은 제외(단, `+`, `&`, `포함`, `세트`가 있는 묶음 판매 글은 유지). 검색어 자체에 그 단어가 있으면 적용하지 않음
- 그래도 남은 저가 글을 거르기 위해 상위 25% 가격의 30% 미만은 제외
- 출처별로, 그리고 두 곳을 합쳐서 사분위 범위(IQR) 기준 극단값을 뺀 뒤 중간값·가격대(하위 25%~상위 25%)·평균 계산
- 새 제품가: 다나와 검색 결과 중 **검색어가 모두 들어 있는 상품**의 최저가(중고·해외구매·리퍼·액세서리·다른 제품과 묶은 구성 제외)
  - 다나와는 검색어와 다른 신제품을 앞에 보여 주는 경우가 있어(예: 워치2 → 워치8) 숫자가 들어간 모델명(워치2·아이폰16 등)은 반드시 일치하는 상품만 사용
  - 숫자가 없는 단어(창문형·에어컨 등)는 다나와 상품명에 없는 경우가 많아(예: 삼성 "윈도우핏") 필수로 두지 않고, 많이 맞는 상품을 우선
  - 숫자는 앞뒤 숫자까지 구분함("워치2"는 "워치8"·"워치 20mm"와 일치하지 않음)
  - 아이패드·아이폰·에어 등 흔한 한글 표기는 영문 상품명(iPad·iPhone·Air)으로도 맞춰 봄
  - 검색어에 없는 파생 모델(프로·플러스·클래식 등)보다 기본 모델을 대표 제품으로 우선
  - 일치하는 새 제품이 없으면 "찾지 못했습니다"로 안내. 새 제품 판매 없이 출시가만 남은 제품은 출시가 사용
  - 단종 추정 제품은 출시가로 표시: 다나와 등록 후 1년 6개월 이상 지났고 현재 최저가가 출시가보다 비싼 제품(남은 재고에 웃돈이 붙은 경우). 다나와가 단종 여부를 따로 표시하지 않아 이 기준으로 추정함
  - "새 제품 대비 %"는 최근 평균 거래 가격 ÷ 새 제품가 (거래 자료가 없으면 판매 중 매물 중간값 기준)

## 유의사항

- 번개장터·당근마켓·중고나라·다나와 모두 공식 공개 API가 아니므로, 화면 형식이 바뀌거나 접근이 막히면 해당 출처만 "조회 실패"로 표시되고 나머지는 계속 나옵니다. 개인 참고용으로만 쓰는 것을 전제로 합니다.
- 당근마켓은 같은 접속 주소에서 짧은 시간에 조회가 반복되면 매물을 비워서 돌려줍니다(첫 조회는 정상, 곧바로 다시 조회하면 0건). 그래서 다음과 같이 반복 조회를 줄입니다.
  - 화면: 10분 안에 같은 검색을 다시 누르면 당근에 묻지 않고 저장된 결과를 보여 줌("n분 전에 조회한 결과" + 새로 조회 버튼)
  - 화면: 새로 조회했는데 당근만 비어 있으면 24시간 안의 이전 당근 결과로 대신 표시하고 조회 시각을 함께 표시
  - 함수: 전체 조회에서는 당근을 7초까지만 기다림. 늦으면 나머지 결과를 먼저 보여 주고 당근은 이어서 조회(당근 한 번 조회는 최대 20초까지 대기)
  - 측정 결과 당근은 같은 접속 주소에서 약 20초에 1번 정도만 매물을 내주고, 그보다 자주 물으면 빈 결과를 줌(많이 몰리면 3~4분간 계속 빈 결과). Supabase 서버 주소는 다른 사용자와 같이 쓰므로 이 한도를 나눠 씀
  - 함수: 중고거래 전용 검색(최대 약 280건)이 제한에 걸려 비면, 당근 통합검색(/kr/search/?q=)의 중고거래 부분(최대 12건)으로 바로 대체. 통합검색은 전용 검색이 막혀 있을 때도 대부분 결과를 줌(측정 결과). 화면에는 "빠른 검색 결과"로 먼저 보여 주고 전체 목록은 이어서 확인해, 받아지면 전체 결과로 바꿈
  - 함수: 옛 주소(/kr/buy-sell/?search=)는 새 주소로 넘기는 요청이 한 번 더 생겨 한도를 두 배로 쓰므로, 최종 주소(/kr/search/buy-sell/?q=)로 바로 요청
  - 화면: 당근이 비었거나 늦으면 25·25·30·35·45초 간격으로 최대 5회(약 2분 40초) 천천히 다시 조회하고, 전체 예정 시간 대비 경과를 주황색 진행 막대 하나로 표시(한 방향으로만 채워지고 문구는 조회 횟수만 바뀜). 끝내 못 가져오면 "다시 확인" 버튼 표시
  - 조회 중 다른 검색을 시작하면 이전 당근 조회는 멈춤
  - 함수: 당근 결과를 30분간 저장해 재사용(함수가 켜져 있는 동안), 빈 결과에 대한 재시도는 하지 않음
- 저장된 결과는 이 브라우저에만 남으며 "기록 모두 지우기"나 검색어의 ×로 함께 지워집니다.
- 출시가가 표시되지 않은 제품은 단종이어도 최저가로 표시됩니다.
- 조회 결과는 10분간 캐시됩니다.
- 다나와는 같은 서버 주소에서 요청이 몰리면 잠시 403(접근 거부)을 줍니다. 함수는 다나와 결과를 6시간 저장하고 403이면 1.5초 뒤 한 번 더 시도하며, 그래도 실패하면 화면이 다른 지역 서버(도쿄 → 미국 서부)로 다시 요청합니다. 다른 출처(번개장터·중고나라·보상판매)도 실패하면 같은 방식으로 재시도합니다.

## 화면 표시 기준

- 조회 버튼을 누르면 화면이 출처마다(번개장터·거래완료·중고나라·당근·다나와·보상판매) 따로 요청해, 먼저 도착한 결과부터 바로 보여 줍니다. 가장 느린 곳(다나와 약 5초)을 기다리지 않습니다. 아직 안 온 출처는 "불러오는 중…"으로 표시
